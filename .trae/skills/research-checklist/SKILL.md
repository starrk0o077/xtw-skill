# 研究方案 HTML Checklist 生成器

## 概述

把用户给出的一份研究方案（或任何需要跟踪的多步骤计划）自动转换为一个**单文件、自包含的 HTML checklist**，用户在浏览器中双击打开即可交互式地勾选已完成项，勾选状态通过 localStorage 自动持久化。

方向不限（单细胞、空间转录组、生信、多组学、临床分析等），但默认面向**生物信息 / 肿瘤研究**场景拆解阶段。

## 触发条件

当用户的请求符合以下任一特征时，**主动加载本 skill 并进入 checklist 生成流程**：

- 明确给出一份方案 / 计划 / 任务清单，希望做成可跟踪的完成清单
- 使用触发词：「方案」「计划」「checklist」「清单」「跟踪进度」「检查完成了哪些工作」
- 描述多个研究阶段或分析步骤，希望结构化呈现

## 核心行为

### 1. 解析方案并拆为阶段

将用户提供的方案分解为若干逻辑阶段。若用户未指定，**默认**按生信研究的典型流水线拆分为以下阶段（可根据实际方案增删）：

1. 数据获取与质控
2. 基因集 / 分子基础构建
3. 差异分析与功能富集
4. 活性 / 打分计算
5. 空间 / 生态位特征分析
6. 临床转化与预后
7. 成果图件与产出

### 2. 每阶段列出具体任务子项

每个子项必须包含三要素：

- **任务名**（加粗，对应 HTML 中的 `<div class="t">`）
- **一句补充说明**（note，对应 `<div class="note">`）：该步骤做什么、用到哪些数据或工具、产出是什么
- **完成状态**：若从上下文能判断某步骤已完成（例如之前对话里提到数据已下载、某分析结果已产出），标记 `data-done="true"` 并附带结果要点；否则不写 data-done

### 3. 输出为单文件 HTML

**硬约束**：HTML 必须是单文件、无外部依赖（不引用外链 CSS / JS / 字体 / 图标），双击即可在现代浏览器中打开运行。

### 4. 文件命名与存放

- 默认保存到**当前工作目录**；若用户有既定项目目录（如 `Downloads/<项目名>/`），放入对应目录
- 命名格式：`<项目标识>_完成检查清单.html`，例如 `TCGA-PAAD_完成检查清单.html`

## 输出格式规范（强约束，务必遵守）

### 配色与字体

- 背景：`#f2f6f3`
- 主色（深青）：`#0a6b5c`
- 辅助色（浅绿）：`#7fb59a`
- 点缀色（暖橙）：`#d49a6a`
- 文字色：`#1f3a36`
- **禁止**大面积使用亮蓝 / 高饱和蓝色
- 字体优先级：`"PingFang SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif`

### 结构元素

HTML 文档必须包含以下区块：

| 区块 | 说明 |
|------|------|
| `<header>` | 方案标题 + 主题标签 |
| 进度摘要卡片 | 显示「已完成 N / 总数」、百分比、进度条（元素 ID 必须为 `barFill`） |
| 多段 `<section>` | 每个 `<section>` 对应一个阶段，阶段头部含数字徽章 `<div class="stage"><div class="num">N</div><div class="cat">阶段名</div></div>` |
| 任务列表 `<ul class="items">` | 每个任务为一个 `<li>`，可选属性 `data-done="true"` 表示初始为已完成 |
| `<footer>` | 包含「重置全部勾选状态」按钮，点击弹 `confirm()` 二次确认 |

### 任务项结构（参考模板）

```html
<li data-done="true">
  <div class="txt">
    <div class="t">TCGA-PAAD 转录组数据下载</div>
    <div class="note">从 GDC Portal 下载 STAR Counts 与 clinical supplement，约 190 例胰腺腺癌样本。</div>
  </div>
</li>
<li>
  <div class="txt">
    <div class="t">数据质控与预处理</div>
    <div class="note">过滤低表达基因，批次校正，PCA 聚类检查离群样本。</div>
  </div>
</li>
```

### 交互与持久化

- 每条 `<li>` 可点击切换 `.done` class，已完成项显示 ✓ 对勾、任务名划线变灰
- 点击后实时刷新进度数字与进度条宽度（百分比写入 `#barFill` 的 `width` style）
- 使用 `localStorage` 保存勾选状态，key 格式为 `<项目标识>_checklist_v1`（项目标识从 header 标题或文件名提取）
- 每个条目按下标存储：`item_0`、`item_1`、`item_2` …；初始化时**优先读 localStorage 中已保存的值**，若不存在则回退到 `data-done` 属性
- 底部「重置」按钮调用 `localStorage.removeItem()` 并刷新页面

## 生成流程

收到方案内容后按以下步骤执行，**不要让用户重复输入已经给出的信息**：

1. **提取项目标识**：从方案标题或核心关键词推断（例如方案里提到 TCGA-PAAD，项目标识就是 `TCGA-PAAD`）
2. **拆解阶段**：根据方案内容决定阶段划分，少则 2-3 阶段、多则 7-8 阶段均可，保持逻辑清晰
3. **列举任务**：每阶段 3-10 个子项，避免过粗也避免过细
4. **标记完成状态**：扫描用户上下文，已完成的步骤标 `data-done="true"`
5. **生成 HTML**：一次性产出完整文档，所有 CSS / JS 内嵌于 `<style>` / `<script>` 标签
6. **落盘并返回路径**：保存到目标目录，告知用户文件名与位置

## 示例触发

**用户输入**：
> 帮我把 TCGA 胰腺腺癌的分析方案做成 checklist。步骤大概是：下载 GDC 数据 → 质控标准化 → 差异分析 → GO/KEGG 富集 → ssGSEA 打分 → 空间特征 → Cox 预后。数据我已经下好了，跑了 DESeq2 差异分析，富集也出图了。

**Skill 输出**（行为层面）：
- 推断项目标识为 `TCGA-PAAD`
- 识别已完成步骤：数据下载、差异分析、富集分析
- 生成含 7 阶段约 20+ 子项的 HTML，前三阶段中已完成项自动打勾
- 保存为 `TCGA-PAAD_完成检查清单.html`

## 注意事项

- **只生成一个 HTML 文件**，不额外创建 README、辅助脚本或资源目录
- **不要主动创建文档**（如 .md 进度说明），除非用户另有明确要求
- HTML 中的中文文本保持原样，HTML 标签、类名、ID、属性名用英文
- 若用户提供的方案非常简略，主动基于生信研究常识补全合理子项，同时在 header 下注明「清单由 AI 根据方案自动补全」
