# Course → MP Series (课程转公众号 1+3 合集)

将一套课程 / 讲义 / 系列资料，转换为公众号后台可粘贴、可一次 1+3 合集的推文，并直接创建草稿。本技能规范化了"读材料 → 拆三课 + 主条 → 排 HTML → 生成图 → 建草稿"的完整流程。

## 触发场景

- 用户给出一套课程（多篇讲义 / 课件 / 大纲 / 知识库条目），要求写成公众号推文。
- 用户明确要"1+3"（1 主条 + 3 子条）或"1+2"合集形式。
- 用户要求"基于这些内容写成合集推文""课程转成文章"。

## 核心原则（复用 wechat-science-writer 的风格）

- **用资讯的壳装学术的内容**：标题抓人、开头一屏讲清"这课讲什么、为什么值得做"，正文用真实细节（方法、平台、参数、样本量、量化结果）推进，信息密度高，拒绝灌水。
- 如果本工作区存在 `wechat-science-writer` 技能，正文风格与 HTML 排版规范直接继承其对应对照（大段距、章节 `#0a6b5c` 加粗标题、结果小节阿拉伯数字、行内容器 `font-size:16px / line-height:1.9 / 段距 26px`）。
- 封面一律柔和低饱和（深藏青 / 暖灰 / 暖棕 / 雾灰），**避开大面积亮蓝色**。

## 文章结构（每篇统一）

- 主条（总览）：开篇抛出"为什么这套内容值得学/值得做"→ 全流程主线梳理 → 要点式章节 → 学习/落地建议。
- 每条子条对应一节课/一处重点：资讯化开场 → 分节拆解（一、二、三…）→ 每节给可落地的关键信息 → 小结。
- 内容必须**忠于原始材料**：平台名、参数、阈值、数字、结论取自讲义原文，不得编造；缺失或不确定处以"待核实"占位。

## 1+3 合集结构（强约束）

- 一次 `draft/add` 调用，`articles` 数组传 **4 条**（1 主条 + 3 子条）。若用户要 1+2 则为 3 条。
- **全部为真正内容，严禁在主条放"汇总介绍/导览"页**。
- 主条按价值/优先级排序；4 篇标题句式、字数密度、收尾风格保持一致。

## 执行流程

1. **读取材料**
   - 用户已上传文件 / 已知路径 → 直接读取。
   - 来源是 ima 知识库 → 先 `seasknowledge_base` 找库、`get_knowledge_list` 列条目、`get_media_info` 拿内容，再读取。
   - PDF → 参考 pdf 技能的 `extract_pages` 逐页提取 + 关键词检索，避免整段丢上下文。
2. **拆解**
   - 识别课程册数/课时数，确立"总览主条 + 每课一条子条"的对应；若课时多，只挑最核心的 3 课或合并同类。
3. **撰写正文 HTML**
   - 用 100% 行内 style（公众号粘贴会剥离 `<style>` 与 CSS 类）。
   - 中文专有名词给全称 + 缩写，关键术语 `<b>` 标出。
4. **生成封面**
   - 可用 `GenerateImage` 生成 4 张柔和概念图；风格统一。
5. **上传封面并建草稿**
   - 调用微信 `token → material/add_material → draft/add`。
   - 凭据：`appid` / `secret` 从用户提供或既有配置读取；不写死敏感信息到技能。
   - 网络：微信/ima API 偶发 `fetch failed`，需重试（指数退避 2s×3）。
6. **结果汇报**
   - 报告合集的 `media_id`、结构（1+3 各条标题）、执行链路，提示用户前往草稿箱验收。

## 交付物

- 直接创建的公众号合集草稿（media_id）。
- 可选：正文 HTML 与封面图文件（便于复用/改稿）。

## 备注

- **不做删除**：旧草稿由用户自行清理，助手只创建新草稿。
- 若遇 IP 未在白名单错误，上报当前出口 IP 并等待用户放行，不擅自绕过。
